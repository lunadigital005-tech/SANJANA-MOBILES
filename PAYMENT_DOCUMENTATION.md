# LUNA Payment Gateway & Refund Management Documentation

---

## 1. Overview & Payment Methods

LUNA provides a secure, modern payment processing workflow supporting:
1. **Razorpay Standard Gateway**: UPI, Credit/Debit Cards, NetBanking, and Mobile Wallets.
2. **Loyalty Coins (Full Payment)**: When customer coin balance covers 100% of the payable order amount.
3. **Hybrid Mixed Payment**: Partial coin redemption combined with Razorpay for the remaining balance.

---

## 2. Server-Side Razorpay Order Creation

When a customer submits the checkout form:
1. The backend verifies real-time stock and creates a 15-minute reservation.
2. The pricing engine calculates `final_payable_amount`.
3. If `final_payable_amount > 0`:
   - A server-to-server request generates a Razorpay Order:
   ```python
   amount_in_paise = int(round(final_payable_amount * 100))
   razorpay_order = razorpay_client.order.create({
       "amount": amount_in_paise,
       "currency": "INR",
       "receipt": f"rcpt_{order_id}",
       "notes": { "order_id": order_id, "user_id": user_id }
   })
   ```
4. The backend stores `razorpay_order_id` in the order record and returns it to the client.

## 4. Cryptographic Signature Verification & Anti-Tamper Defense

Never trust client assertions of payment success. The backend verifies the cryptographic signature generated by Razorpay's private key:

```python
import hmac
import hashlib

def verify_razorpay_signature(razorpay_order_id: str, razorpay_payment_id: str, razorpay_signature: str) -> bool:
    message = f"{razorpay_order_id}|{razorpay_payment_id}".encode("utf-8")
    generated_signature = hmac.new(
        key=settings.RAZORPAY_KEY_SECRET.encode("utf-8"),
        msg=message,
        digestmod=hashlib.sha256
    ).hexdigest()
    
    # Constant-time comparison prevents timing attacks
    return hmac.compare_digest(generated_signature, razorpay_signature)
```

If the signature fails comparison, the request is rejected with `HTTP 400 Bad Request`, stock reservations are not committed, and the order remains `PENDING`.

## 5. Webhook Processing & Idempotency

Razorpay sends server-to-server webhook notifications (e.g. `payment.captured`, `payment.failed`, `refund.processed`).

### Signature Validation
Webhooks include an `X-Razorpay-Signature` header computed over the raw request payload using `RAZORPAY_WEBHOOK_SECRET`.

### Replay & Duplicate Prevention
To prevent processing the same webhook event twice:
```python
processed_webhook_events = set()

@router.post("/orders/webhook")
async def handle_razorpay_webhook(request: Request):
    raw_body = await request.body()
    signature = request.headers.get("X-Razorpay-Signature", "")
    
    # Verify HMAC
    if not verify_webhook_signature(raw_body, signature, settings.RAZORPAY_WEBHOOK_SECRET):
        raise HTTPException(status_code=400, detail="Invalid webhook signature")
        
    payload = json.loads(raw_body.decode())
    event_id = payload.get("event_id")
    
    # Idempotency guard
    if event_id in processed_webhook_events:
        return {"status": "ignored", "reason": "duplicate_event"}
        
    processed_webhook_events.add(event_id)
    # Process event safely...
```

## 6. Refund Management

### 6.1 Order Rejection & Cancellation
When an admin rejects a paid order (`POST /api/v1/admin/orders/{id}/reject`) or a customer cancels:
1. Inventory is restored to available stock.
2. Redeemed loyalty coins are credited back to the customer's wallet.
3. If paid via Razorpay, a full refund is initiated via `razorpay_client.payment.refund(payment_id, amount)`.
4. Order status transitions to `REJECTED` and payment status to `REFUNDED`.

### 6.2 Partial Refunds
- Admins can issue partial refunds (e.g. for a damaged line item).
- The system enforces: `sum(refunds) <= order.total_amount`.
- Any attempt to refund more than the unrefunded balance is rejected with `HTTP 400 Bad Request`.
